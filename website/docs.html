Tincan is a Linux desktop app, with a matching command line and MCP server, that reads and sends text messages through your iPhone over Bluetooth.

Tincan is early alpha software. Expect rough edges and breaking changes before 1.0.

Requirements #

Tincan connects to your iPhone over Bluetooth — the same way a car stereo does — using the Message Access (MAP), Phone Book Access (PBAP), and Apple Notification Center (ANCS) profiles. A local background service (the daemon) holds the connection and keeps an encrypted copy of what it sees. The desktop app, the tincan CLI, and the MCP server all talk to that daemon. Nothing goes through a cloud server.

  • 64-bit Linux (x86_64 or arm64) with glibc 2.35 or newer: Ubuntu 22.04+, Debian 12+, Fedora 36+, or a current rolling distribution.
  • BlueZ 5.64+ with obexd (often a separate package, such as bluez-obexd).
  • OpenSSL 3 (libssl3 or libssl3t64 on Debian and Ubuntu).
  • systemd, for the background service.
  • A Bluetooth adapter (built-in or USB) and an iPhone nearby.
  • A desktop keyring (GNOME Keyring or KWallet), recommended for storing the database key.
  • Node.js 22.18+ (only if installing the CLI from npm).

Only one computer or car can read an iPhone's messages at a time. Over Bluetooth, iOS shares new texts, contacts, and notifications — not photos, messages you send from the iPhone itself, or your full history. See the full list on the homepage.

Install #

Get the latest packages from the download page.

Desktop app (.deb) #

Recommended on Debian and Ubuntu. Installs the desktop app, the tincan CLI, and the AppArmor profile required on newer Ubuntu. 

sudo apt install ./Tincan-*.deb

Desktop app (AppImage) # 

chmod +x Tincan-*.AppImage
./Tincan-*.AppImage

Requires FUSE 2 (libfuse2 on Ubuntu).

The AppImage carries update information, so AppImageUpdate or AppImageLauncher can update it in place from GitHub Releases. Tincan itself never checks for updates.

Ubuntu 24.04 and newer: AppArmor restricts the unprivileged user namespaces Chromium's sandbox needs, so the AppImage may fail to start. Don't work around this with --no-sandbox — that disables the sandbox around the window rendering texts from strangers. Install the .deb instead, or add a local AppArmor profile from Troubleshooting.

CLI only (npm) # 

npm install -g @beyland/tincan

Installs the tincan CLI, the daemon, and the MCP server without the desktop app.

Verify your download #

Each release includes SHA256SUMS and a signed GitHub Actions build attestation (works for the .deb too). 

sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify Tincan-*.AppImage --repo beyland-dev/tincan

First run and pairing #

The desktop app walks you through setup on first launch. From a terminal, run the same steps: 

tincan setup             # one-time Bluetooth setup (uses sudo)
tincan service install   # start the daemon in the background
tincan pair              # pair your iPhone
tincan doctor            # verify everything works

tincan setup enables BlueZ's experimental mode (required for iPhone notifications) and keeps your adapter presenting itself as a hands-free device so iOS offers message sharing. It restarts bluetooth.service, briefly disconnecting Bluetooth keyboards, mice, and headphones. Run it before pairing — if you paired first, forget the computer on your iPhone, restart the iPhone, and pair again.

  1. Keep your iPhone unlocked on Settings › Bluetooth. Both screens show a six-digit code; accept only if they match. Tincan rejects pairings that skip code verification.
  2. On your iPhone, open Settings › Bluetooth, tap (i) next to your computer and turn on:
    • Show Notifications (or Show Message Notifications on some iOS versions) — lets Tincan read and send messages.
    • Sync Contacts — shows names and photos instead of numbers.
    • Share System Notifications (if shown) — improves group conversation support.
  3. On first sync, iOS shares only the 10 newest inbox messages. From then on, Tincan keeps its own encrypted copy of everything it sees.

Background service #

Keep the daemon running after you close the window so messages and notifications keep arriving. Turn on Run in the background in desktop Settings, or use the CLI: 

tincan service install     # systemd user service: starts at login, restarts on failure
tincan service status
tincan service uninstall

To run the daemon in the foreground instead, run tincan daemon and stop it with Ctrl+C.

The desktop app #

  • Conversations: Appear as messages arrive. Reply from the box at the bottom; send status and retry show under outgoing messages.
  • Drafts: Each conversation keeps its own unsent reply, and a conversation with a draft waiting — yours or an agent's — shows "Draft: …" in the list.
  • Pin or mute: Use a conversation's menu to pin it to the top of the list or turn off its notifications.
  • Hide from agents: Right-click a conversation, or open its info panel, and choose Hide {name} from agents. That hides the person: all their numbers and emails, every conversation with them, every group they're in, and their contact. A group can be hidden on its own too. Everything stays in your list, but AI agents can't see it until you show it to them again, and their messages to someone hidden always wait for you as drafts. Settings › AI agents › Hidden from agents lists everyone you've hidden, and hides anyone else, even a contact or number you've never texted.
  • Notifications: Click a notification to open its conversation. Choose whether notifications show the message, sender only, or nothing in Settings › General. Sign-in codes include a Copy code button.
  • Link previews: Off by default. When turned on in Settings › Messages & Privacy, Tincan fetches page titles and images directly from linked sites. Previews load automatically only in conversations with saved contacts or ones you've replied to; elsewhere, click to load them.
  • Keyboard shortcuts: Ctrl+K command palette, Ctrl+N new message, Ctrl+F search, Ctrl+, settings.
  • Connection help: Open Settings › iPhone for Copy diagnostics (and Fix connection… when messages are blocked, or anytime via Ctrl+K).

The tincan CLI #

Every daemon command is available as a tincan subcommand. Add --json for machine-readable output or --help to any command.

Command What it does
tincan status Daemon and phone connection status
tincan doctor Check Bluetooth, BlueZ, and iPhone permissions
tincan threads List conversations by contact name. Add --verbose to see each conversation's key (its phone number or email), or --json for scripts.
tincan message list <thread> List messages in a conversation
tincan message search <text> Search saved messages
tincan send <to> <text> Send to a number, email, contact name, or thread
tincan message cancel <id> Take back a message still in its send delay
tincan message send-now <id> Send a message in its send delay right away
tincan drafts List agent drafts waiting for you (also tincan draft list)
tincan draft show <id> Show one agent draft, with its full text and what became of it
tincan draft send <id> Send an agent draft (asks first, at a terminal)
tincan draft discard <id> Throw an agent draft away (asks first, at a terminal)
tincan thread mark-read <thread> Mark a conversation read, on the iPhone too
tincan agents hide <name|number|group> Hide a person (all their numbers and emails) or a group from AI agents (tincan agents show shows them again, at a terminal; tincan agents hidden lists who's hidden)
tincan contact search <query> Find a contact by name, number, or email
tincan watch Stream daemon events as they happen
tincan commands List every command (add --json for JSON Schemas)

Prompts and scripts: Sending, deleting, and other changes ask for confirmation (y/N). In scripts, pass --yes (-y) to run without prompting.

Interactive-only commands: Commands that change what AI agents may do or act on what they wrote — tincan settings set (for agent settings), tincan draft send / discard, tincan connect / disconnect, and showing someone to agents again with tincan agents show <name|number|group> — require you to confirm at a real terminal. --yes does not skip that prompt, and they refuse to run from an AI agent's shell. The desktop app's Settings is the easiest way to manage them.

In an agent's shell: When tincan runs inside a detected AI agent's shell, it connects as that agent and follows your agent settings. See CLI: scripts and agents with shell access.

Send delays #

A send delay gives you a moment to change your mind. When you press Send, the message waits on your computer for a few seconds before Tincan hands it to your iPhone. In the conversation it shows as a see-through bubble with Sending in 8s · Undo · Send now under it. Undo takes it back (your text returns to the message box if it's empty), and Send now skips the wait. Ctrl+Z in an empty message box, or Ctrl+Shift+Z anywhere in the conversation, undoes the latest one.

  • Send delay (Settings › Messages & Privacy, sendDelaySeconds) is for messages you write yourself. It's off by default; pick 3 to 60 seconds.
  • Agent message delay (Settings › AI agents, agents.sendDelaySeconds) is for an agent's messages: ones it sends directly, and agent drafts you send. It's 10 seconds by default. While an agent's own send is waiting, the bubble reads Claude Code is sending in 8s · Edit · Cancel and a desktop notification offers Cancel.
  • From the CLI: At a terminal, tincan send counts down on one line and Ctrl+C cancels it. With --json or in a script it returns at once and prints the tincan message cancel <id> to run. Set the delays with tincan settings set --send-delay-seconds 5 and --agents-send-delay-seconds (0–300).

The delay only holds the message on your computer. Once it reaches your iPhone, it can't be unsent — Tincan can't use iMessage's Undo Send. If your computer sleeps through a message's send time, Tincan doesn't send it late: your own message is marked not sent so you can retry it, an agent draft you sent goes back to its queue, and an agent's own send is cancelled.

AI agents #

AI agents can reach Tincan in two ways: over MCP, or by running the tincan CLI from their shell. The same agent settings apply to both.

MCP: agents in your editor or terminal #

tincan mcp is an MCP server that agent apps launch over stdio. Add it to a supported app: 

tincan connect                  # list the apps you can connect
tincan connect claude           # add Tincan to Claude Code
tincan connect claude --print   # print the config without changing anything
tincan disconnect claude        # remove it again

Run tincan connect <agent> and tincan disconnect <agent> yourself: they ask you to confirm at a terminal and refuse to run from an AI agent's shell. --print runs anywhere. Supported apps: copilot (VS Code, Copilot app, and Copilot CLI), claude, codex, cursor, opencode, antigravity, muse, and pi. Any other MCP client can run tincan mcp over stdio. You can also connect apps in Settings › AI agents.

CLI: scripts and agents with shell access #

When tincan runs inside a detected AI agent's shell (Claude Code, Codex, Cursor, Gemini CLI, and others), it connects as that agent — for example Claude Code (CLI) — and prints a line saying so. Your agent settings then apply to everything it runs: nothing works while access is Off, reading follows your choices, phone numbers come back as opaque IDs, and tincan send is an agent's message, so it becomes an agent draft for you or waits for the agent message delay. Commands that change what agents may do, or that send or discard agent drafts, are refused.

Scripts you run from a normal terminal are treated as you, with your full CLI. There's no switch to turn the detection off, and it isn't a wall: an agent with unrestricted shell access can do anything you can, including hiding the signs Tincan looks for.

Agent settings #

Change these in Settings › AI agents, or with tincan settings set --access … at a terminal. First pick an access level; each one shows only the options that make sense for it:

  • Off (the default): agents can't see or send your messages. They can only check that Tincan is running and what access you've given them.
  • Read only: agents read the conversations you choose (contacts only, contacts and people you've replied to, or everyone). They can't send, draft, or change anything.
  • Assistant: agents can also draft and send messages, and manage conversations if you allow it. By default every message they write is an agent draft for you to send; you can also let them text people you've texted yourself, or send without asking. Sends are capped at 10 every 10 minutes unless you change or turn off the limit. Phone numbers, emails, and verification codes stay hidden.
  • Full access: everything you allow, with no send limit, and nothing asks first when sending is set to Always. Only here does the Danger section appear, with Show phone numbers & emails to agents and Show verification codes to agents. Both are off by default. Tincan asks you to confirm before switching to Full access.
Setting In the app Default
agents.access Access: Off (off), Read only (readOnly), Assistant (assistant), Full access (full). Caps every setting below. off
agents.read Reading: Off (off, Assistant and Full access only), Contacts only (contacts), Contacts & people you've replied to (known), Everyone (all) known
agents.send Sending (Assistant and Full access): Ask me (approve), Only people I've texted (replied), Always (always) approve
agents.sendDelaySeconds Agent message delay (Assistant and Full access): Off or 3–60 seconds (0–300 from the CLI), for agents' messages and agent drafts you send 10
agents.sendLimit Send limit per 10 minutes (1–60, or null for none). A message counts when it's queued as a draft, and discarding it doesn't give it back. Assistant only; Full access has no limit. 10
agents.manage Manage conversations (mark read, mute, pin) false
agents.handles Show phone numbers & emails to agents (Full access only, under Danger); visible when on hidden (off: opaque IDs instead of real addresses)
agents.hideCodes Show verification codes to agents (Full access only, under Danger); false when on true (off: codes and short-code senders hidden)
sendDelaySeconds Send delay (Settings › Messages & Privacy): Off or 3–60 seconds, for messages you write yourself. Not an agent setting; see Send delays. 0 (off)

Agent drafts #

Every message an agent writes that needs you — a draft it saves, or a send your settings don't let go straight out — becomes an agent draft. It lands in that conversation's message box, ready to edit, with a small label above it: Drafted by Claude Code · Discard. Press Send to send it as it is or as you've changed it, or Discard to throw it away. The agent's name is self-reported, so treat it as a label, not proof.

  • Drafts queue. Several can wait in one conversation, and for people you have no conversation with yet. The label gains a stepper (‹ 1 of 3 ›) to move between them, or use Ctrl+] and Ctrl+[. If you're already typing, Tincan leaves your text alone and offers View instead. Your own draft is a separate slot that agents never touch.
  • Nothing expires. A draft waits until you send or discard it, and nothing goes unless you press Send. Older drafts show their age.
  • Easy to find. A conversation with a draft shows "Draft: …" in the list, a notification tells you when a new one arrives, and Ctrl+Shift+D opens the next conversation with one.
  • Flagged when it matters. When a draft has something worth a second look — hidden or direction-changing characters, a link to a lookalike address, something that looks like a code, or a long blank stretch — small notes appear next to the label.
  • The agent sees the outcome. It can check whether its draft was sent (and whether you edited it), discarded, or cancelled. It sees your edited text only in conversations it's allowed to read.
  • Still the agent's message. A message you send from an agent draft counts as the agent's, edited or not, and waits for the agent message delay. It never unlocks Only people I've texted; for that, send a message you typed yourself.

How sending decides between a draft and a direct send:

  • Ask me (approve): every message is an agent draft.
  • Only people I've texted (replied): a message goes directly only to someone you've texted yourself. Anyone else — even someone who texted you first — gets a draft.
  • Always (always): messages go directly, after the agent message delay. Messages to people or groups you've hidden from agents are always drafts, at every access level. Under Assistant, a short-code sender or a raw phone number is still a draft too, and every send counts toward the send limit. Under Full access, nothing else becomes a draft.

Drafts an agent saves on purpose always wait for you, whatever Sending says. From a terminal, tincan drafts lists them, and tincan draft show, send, or discard <id> acts on one.

What agents can and can't do #

  • With reading on: List and read the conversations their reading level allows, search those messages, and look up contacts. Anything outside it looks to them as if it doesn't exist.
  • With Assistant or Full access: Write agent drafts, send under the rules above, follow what happened to their drafts, and discard their own drafts while they're still waiting. With conversation management on, mark conversations read, muted, or pinned.
  • Always blocked: Sending or editing their own drafts, cancelling or hurrying a delayed send, retrying a failed one, deleting conversations, messages, or groups, pairing or forgetting the iPhone, and changing settings.
  • Hidden from agents: People and groups you hide from agents never reach them. While Show verification codes to agents is off (the default), short-code and alphanumeric senders (banks, sign-ins) are hidden, and verification codes, magic links, and password-reset links are blanked out.
  • Untrusted tagging and rate limits: Every message, name, group name, and contact field is marked as untrusted external data. Rate limits cover sending, saving drafts, marking read, muting, and syncing, and survive daemon restarts. At most 5 agent drafts wait in a conversation, and 20 per agent.

Use at your own risk. Warning: An incoming message could trick an agent into replying with sensitive information or take actions using other tools you've given it. This is prompt injection. Tincan's guardrails reduce the risk; they cannot eliminate it, and code redaction won't catch every format.

The agent policy is a guardrail, not an OS security boundary. Any program running as your Linux user — including an agent with shell access — can reach Tincan as you. Grant only the access you need, keep sending on Ask me (or choose Read only), and read every agent draft before you send it. A send delay only helps if you're there to cancel.

Privacy and security #

  • Encrypted local database: Messages, contacts, and settings are stored on your computer in an encrypted SQLCipher database (~/.local/share/tincan/tincan.db). Its key lives in your desktop keyring (dev.beyland.Tincan.VaultKey), or falls back to a private key file when no keyring exists (which tincan doctor warns about).
  • Local-only daemon: The daemon listens only on a private local Unix socket. There is no network port, no account, no telemetry, and no Tincan server.
  • No sensitive logging: Message text, phone numbers, and contact names are never written to logs.
  • Optional network traffic only: The only internet traffic is link previews and spell check (which downloads a spelling dictionary from Google once). Both are off by default; with both off, the app makes no outbound requests. Link previews only fetch over HTTPS: plain http:// links get no preview.

Read the full threat model in docs/security.md. Found a vulnerability? Report it privately through GitHub's private vulnerability reporting.

Troubleshooting #

Start with tincan doctor. It checks each component and prints how to fix what's missing.

  • No Show Notifications or Sync Contacts toggle on the iPhone: Run tincan setup, forget this computer on the iPhone, restart the iPhone, then pair again.
  • "Busy": Another computer, car, or Bluetooth messaging app holds the iPhone's message session. Disconnect it and try again.
  • Messages stopped after re-pairing: Forget the pairing on both Linux (tincan device forget) and the iPhone, restart the iPhone, then pair again from Tincan.

More fixes are in docs/troubleshooting.md. When opening an issue, attach tincan doctor --report — it masks Bluetooth addresses, device names, and home-folder paths. Read it before pasting, and never include message text, phone numbers, or contact names.

Uninstall # 

tincan disconnect <agent>   # for each agent app you connected
tincan service uninstall   # stop and remove the background service
tincan setup uninstall     # undo Bluetooth setup (uses sudo)

Then remove the app itself:

  • .deb: Run dpkg -S /opt/Tincan to find the package name, then sudo apt remove <name>.
  • AppImage: Delete the file (and /etc/apparmor.d/tincan-appimage if you created one).
  • npm: npm uninstall -g @beyland/tincan

Your messages stay in ~/.local/share/tincan until you delete that folder. Remove the database key (dev.beyland.Tincan.VaultKey) using your keyring app (such as Passwords and Keys). Finally, forget this computer on your iPhone under Settings › Bluetooth.
